## Purpose

Make the open-core repository safe and understandable for contributors while keeping commercial claims tied to reproducible pilot evidence.

## ADDED Requirements

### Requirement: Contribution readiness assessment
The repository SHALL document present support and gaps for setup, CI, issue and pull request intake, security disclosure, conduct, governance, maintainer triage and releases.

#### Scenario: New contributor path
- **WHEN** a new contributor follows the documented setup
- **THEN** they can run the stated checks and identify the supported contribution route

### Requirement: Policy evidence boundary
The project SHALL not invent governance, enforcement, security or release policy details without an approved source of truth.

#### Scenario: Unapproved policy gap
- **WHEN** a required policy has no approved detail
- **THEN** the readiness plan labels it as a decision required rather than publishing a fictional rule

### Requirement: Evidence-backed commercial discovery
The project SHALL begin discovery only after reproducible pilot proof and SHALL offer fixed-scope compatibility audits and implementation packages only with claims bounded by platform and pilot evidence.

#### Scenario: Communication preparation
- **WHEN** an outreach or landing-page claim is drafted
- **THEN** it maps to a named capability, platform and proof artifact

### Requirement: Sequenced communication
The project SHALL communicate in this order: a short before-and-after pilot artifact with reproducible evidence, OSS release with quickstart and audit, evidence-based technical content, targeted maintainer outreach based on a public gap, then further domain case studies.

#### Scenario: Pre-proof communication
- **WHEN** reproducible pilot evidence is incomplete
- **THEN** the project does not use broad marketplace messaging, generic mass outreach, or unsupported AI infrastructure claims

### Requirement: Audit-first call to action
The free developer call to action SHALL be `intentlane audit` and SHALL explain the gap between shortcuts and schema-backed Siri or Apple Intelligence readiness.

#### Scenario: Public audit explanation
- **WHEN** audit documentation is published
- **THEN** it scopes every finding by platform, version and available evidence

### Requirement: Deferred compatibility catalog
The project SHALL treat a public compatibility catalog as later verified social proof, not as the initial acquisition channel.

#### Scenario: First commercial materials
- **WHEN** the first audit and implementation materials are prepared
- **THEN** they prioritize the pilot artifact and audit over a public app catalog
