## Context

CONTRIBUTING.md and CI already provide partial contributor support. Governance, conduct, security reporting, maintainer triage, releases and information architecture need an evidence-based readiness assessment before policies are written.

## Goals / Non-Goals

**Goals:** separate evidence from gaps, make contribution setup reproducible, sequence communication after pilot proof.

**Non-Goals:** marketplace, SaaS, public repository catalogue, repository-reading AI proposals or external outreach.

## Decisions

- Start with a readiness matrix that cites existing repository evidence.
- Add policy files only after explicit owner decisions for their unresolved details.
- Keep OSS free tooling distinct from paid audit and domain implementation work.

## Risks / Trade-offs

- Premature governance language → record a decision gap instead of inventing enforcement.
- Marketing ahead of proof → gate communication on reproducible pilot artifacts.
