# NetNewsWire ASRi pilot

This is the short before-and-after artifact for the first public macOS 27
pilot. It records what changed, the commands that reproduce it, and what
remains unproven. NetNewsWire is a third-party application; nothing here
suggests that its authors reviewed, endorsed or accepted any of this work, and
the fork was never pushed upstream.

## Current pilot state, 2026-09-23

This section supersedes the historical Reader-only notes below.

The fork now uses the primary macOS 27 schemas `.system.searchInApp` and
`.system.open`, an `IndexedEntity` article model, and a direct app-navigation
adapter. The clean `NetNewsWire-AppIntents` integration plan passes 5 of 5
tests on macOS 27.0 build 26A428 with zero build errors and zero build warnings.
It proves Alpha resolution, indexed Spotlight querying, opening Alpha, marking
Beta read, and rejecting an invented title without selecting Gamma.

This is strong automated system-surface evidence, not a claim that the visible
Spotlight and spoken Siri journeys have passed. Those are still manual gates,
followed by independent reproduction. The full command, result path, fixes and
rejected causes are in `PILOT-NETNEWSWIRE-VALIDATION-RUNBOOK.md`.

## What the app had before

NetNewsWire ships one App Intent and one shortcut provider, both under `iOS/`:
`AddFeedAppIntent` and `NetNewsWireAppShortcuts`. It has no `AppEntity`, no
`AppEnum`, no `EntityQuery` and no schema conformance. On macOS 27 the audit
therefore credited it with nothing: the iOS-only intent is not compiled by a
macOS target, which is the target-scoped audit rule.

## What the fork currently proves

The fork is a disposable clone outside the product repository. Three files were
added or edited:

- `Mac/IntentLanePilot/IntentLaneGenerated.swift`, generated from a contract
  that conforms one entity to `reader.page` and one intent to
  `reader.openPage`.
- `Mac/IntentLanePilot/IntentLaneArticleAdapter.swift`, the adapter the app
  owns: a resolver over `AccountManager` and a handler that marks an article
  read.
- `Mac/AppDelegate.swift`, two local edits: a deep-link entry point and one
  registration call at launch.

The contract declares `reader.page` and `reader.openPage`. That was a useful
generator and metadata exercise, but it is **not** a Siri AI proof. Apple
classifies the entire Reader domain as Shortcuts-only: it can expose actions in
Shortcuts, but it does not make the conforming types discoverable by Apple
Intelligence or Siri.

## Reproduction

```sh
git clone --depth 1 https://github.com/Ranchero-Software/NetNewsWire.git
cd NetNewsWire
git checkout 0184ca38c586078117a21f96f68eef78d39b8f68
bash buildscripts/updateSecrets.sh
node <intentlane>/packages/cli/dist/index.cjs generate -c <contract> -o Mac/IntentLanePilot
xcodebuild -project NetNewsWire.xcodeproj -scheme NetNewsWire \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath <build> CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build
xcodebuild test -project NetNewsWire.xcodeproj -scheme NetNewsWire \
  -destination 'platform=macOS' -derivedDataPath <build> \
  -only-testing:NetNewsWireTests/IntentLanePilotTests \
  EXCLUDED_SOURCE_FILE_NAMES='*.applescript' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
```

`updateSecrets.sh` is not optional: `SecretKey.swift` is generated from a
template and is not versioned, so the build fails without it. The AppleScript
exclusion is needed because three upstream scripting resources do not compile
under this toolchain.

## Correct ASRi target

The pilot must now prove the primary macOS 27 path, not Reader automation:

1. Model feed entries as stable article entities and implement the query used
   to resolve them.
2. Implement the `.system.searchInApp` and `.system.open` schemas with the exact
   type shapes generated by the installed Xcode 27 SDK.
3. Make the article entities `IndexedEntity` instances and wire their full
   indexing lifecycle to feed refreshes, updates, and removals.
4. Add `AppIntentsTesting` coverage for Alpha resolution, opening Alpha, and
   an invented title that resolves to nothing. Gamma must remain a distinct
   indexed article, never a fallback match for Alpha or the invented title.
5. Prove Spotlight and a real Siri AI interaction on macOS 27, with the exact
   OS build, locale, fixture and result recorded in the ledger.

`mark beta read` is not part of this ASRi proof. It has no matching primary
schema for an RSS article’s read state, so it may later be kept as a custom
automation action, but never used to substantiate a Siri AI claim.

## Historical evidence only

The nine hosted acceptance cases pass, including the four that need the pilot
feed: subscribe, find Alpha, mark Beta read and reset it, and the negative case
that must never match Gamma.

The extracted metadata of the real `NetNewsWire.app` carries what the Reader
schema asks for:

- `IntentLaneArticleEntity` with `assistantDefinedSchemas` naming
  `ReaderPageEntity`.
- `OpenArticle` with `openAppWhenRun` true, `outputFlags` 0, and the system
  protocols `AssistantIntent` and `OpenEntity` alongside `ReaderOpenPageIntent`.

The audit of the fork moves in four steps, all limited to Reader automation:

| State | Score | Discovery |
| --- | --- | --- |
| Before any IntentLane Swift | 0/100 (none) | none |
| After the native intents and the entity | 10/100 (early) | shortcuts-only |
| After conforming the entity to `reader.page` | 15/100 (early) | shortcuts-only |
| After conforming the action to `reader.openPage` | 19/100 (early) | shortcuts-only |

The score is low because it measures breadth across the whole catalogue, not
the quality of these journeys. More importantly, Reader conformance cannot move
the `discovery` field to `schema-backed`: that label is reserved for a primary
Siri AI schema and must not be used for a Shortcuts-only domain.

## Defects the pilot found in IntentLane

Two real defects were fixed in the product, not in the fork:

1. The generated code failed under Swift 6 concurrency: the entity query was a
   `static var` and the resolver and handler protocols were not `Sendable`.
2. A conformed entity could not be constructed, because `@Property` inside an
   `AppEntity` is a typealias to `EntityProperty`, a final class with no
   `init(wrappedValue:)`, so the generated entity now declares an explicit
   initializer.

## Not proven

- System search/open. The fork has no `.system.searchInApp` or `.system.open`
  implementation.
- Spotlight. No article indexing lifecycle was implemented or observed.
- Siri AI. No process can drive Siri, so the manual positive and negative cases
  are still open. Reader metadata proves only Shortcuts registration, never
  live semantic resolution or natural-language execution.

Because of those three, the pilot has not reached a terminal evidence ledger,
and no marketing claim should be made from it beyond the metadata and audit
facts above.
